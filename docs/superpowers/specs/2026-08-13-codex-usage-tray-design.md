# Codex Usage Tray 설계

## 목표

Windows 알림 영역에 상주하면서 현재 Codex 사용 제한의 남은 비율을 숫자와 색으로 표시한다. 아이콘을 클릭하면 모든 제한 구간의 남은 비율과 초기화 시각을 확인할 수 있어야 한다.

추가로 로컬 Codex 작업이 사용자의 응답이나 승인을 기다리거나 완료되었을 때, 다른 창에서 일하고 있어도 어느 프로젝트·채팅·터미널인지 즉시 알 수 있어야 한다.

## 사용자 경험

- 앱을 실행하면 일반 창을 띄우지 않고 알림 영역에 아이콘을 만든다.
- 아이콘 숫자는 가장 적게 남은 활성 제한 구간의 잔여율이다.
- 잔여율이 50% 초과면 초록, 20~50%면 노랑, 20% 미만이면 빨강으로 표시한다.
- 아이콘을 왼쪽 클릭하면 제한 구간별 상세 정보와 마지막 갱신 시각이 나타난다.
- 아이콘을 오른쪽 클릭하면 `상세 보기`, `새로고침`, `Codex 로그인`, `Windows 시작 시 실행`, `종료` 메뉴가 나타난다.
- 5분마다 자동 갱신하고 사용자가 언제든 수동 갱신할 수 있다.
- 로컬 Codex가 새 요청을 시작하면 작업 기록을 `진행 중`으로 갱신한다.
- 권한 승인을 요청하면 `승인 필요 · 프로젝트 · 채팅` 팝업을 표시한다.
- 턴이 끝나면 `작업 완료 · 프로젝트 · 채팅` 팝업과 마지막 응답 요약을 표시한다.
- 알림을 클릭하면 감지된 원본 터미널 창을 앞으로 가져오고, 창을 찾지 못하면 작업 기록을 연다.
- 최근 작업 알림 50개를 메모리에 유지하고 앱을 종료하면 삭제한다.

## 데이터 원본과 인증

앱은 화면 스크래핑, 브라우저 쿠키, OpenAI API 키를 사용하지 않는다. 설치된 Codex CLI를 `codex app-server`로 실행하고 표준 입출력 JSONL 통신으로 다음 순서를 수행한다.

1. `initialize` 요청과 `initialized` 알림으로 연결을 초기화한다.
2. `account/rateLimits/read`를 호출한다.
3. `rateLimitsByLimitId`가 있으면 모든 버킷을 사용하고, 구버전 호환 필드인 `rateLimits`만 있으면 단일 버킷으로 대체한다.
4. `usedPercent`를 0~100 범위로 제한한 뒤 `100 - usedPercent`로 잔여율을 계산한다.
5. `resetsAt` Unix 초 값을 Windows 현지 시각으로 변환한다.

Codex 로그인 토큰은 Codex CLI가 소유·갱신하며 이 앱은 토큰을 읽거나 저장하지 않는다.

## 작업 알림 원본

사용자 수준 `~/.codex/hooks.json`에 앱 전용 Hook 세 개를 병합한다.

- `UserPromptSubmit`: 세션·턴·작업 폴더·사용자 요청으로 `진행 중` 상태를 만든다.
- `PermissionRequest`: 세션·턴·작업 폴더·도구·명령으로 `승인 필요` 상태를 만든다. Hook은 승인 여부를 결정하지 않고 정상 Codex 승인 화면을 그대로 유지한다.
- `Stop`: 세션·턴·작업 폴더·마지막 응답으로 `완료` 상태를 만든다. Hook은 Codex에게 계속 작업하라는 결정을 반환하지 않는다.

별도 콘솔 브리지 실행 파일이 Hook JSON을 표준 입력으로 받고, 현재 사용자만 접근 가능한 Windows Named Pipe로 트레이 앱에 전달한다. 브리지는 부모 프로세스 계층에서 터미널 창 제목·PID·창 핸들을 최선 노력으로 찾는다. 찾지 못해도 프로젝트 폴더명과 세션 ID로 구분한다.

웹 및 ChatGPT 데스크톱 작업은 ChatGPT 자체 완료·권한·질문 알림을 사용한다. 외부 앱이 정확한 웹 채팅 ID와 상태를 받는 공개 인터페이스가 없으므로 화면 감시, 브라우저 확장, 쿠키 추출은 구현하지 않는다. 앱 메뉴에서 공식 알림 설정 안내를 연다.

## 구조

### `CodexUsageTray.Core`

Windows UI에 의존하지 않는 .NET 8 라이브러리다.

- `JsonRpcConnection`: JSONL 요청/응답 ID 상관관계, 알림 무시, 오류 전달
- `CodexAppServerClient`: Codex 프로세스 생명주기와 초기화
- `RateLimitParser`: 공식 응답의 단일/복수 버킷 호환 파싱
- `UsageSnapshot`: 표시 가능한 제한 구간과 전체 상태
- `UsagePresentation`: 잔여율, 색상 상태, 기간 라벨 계산

### `CodexUsageTray`

`net8.0-windows` WinForms 실행 파일이다.

- `TrayApplicationContext`: 트레이 메뉴, 5분 타이머, 갱신 직렬화, 앱 종료
- `TrayIconRenderer`: 32px 아이콘에 잔여율 숫자와 상태색 렌더링
- `UsageFlyoutForm`: 상세 제한 구간, 초기화 시각, 오류 및 갱신 상태
- `StartupRegistration`: 현재 사용자 레지스트리의 Run 항목 관리
- `ActivityPipeServer`: 브리지 이벤트 수신과 현재 사용자 한정 IPC
- `ActivityHistoryForm`: 진행 중·승인 필요·완료 기록과 원본 터미널 열기

### `CodexUsageTray.EventBridge`

Codex Hook이 호출하는 짧은 콘솔 실행 파일이다. Hook 입력을 정규화하고 트레이 앱을 시작한 뒤 이벤트를 Named Pipe로 보낸다. 네트워크를 사용하지 않으며 Hook 결정이나 Codex 출력은 변경하지 않는다.

## 오류 처리

- Codex CLI 미설치: 회색 `?` 아이콘과 설치 안내를 표시한다.
- Codex 로그아웃: 회색 `!` 아이콘과 로그인 메뉴 사용 안내를 표시한다.
- 네트워크 또는 App Server 일시 오류: 직전 정상값을 유지하되 상세 창에 오류와 마지막 정상 갱신 시각을 표시한다.
- 응답 형식 변경: 앱을 종료하지 않고 `응답을 해석할 수 없음` 상태로 전환한다.
- 중복 새로고침: 동시에 하나만 수행하고 추가 요청은 무시한다.
- App Server 종료: 다음 갱신 시 프로세스를 한 번 새로 시작한다.
- Hook 입력 형식 변경: Codex 작업을 방해하지 않고 브리지만 오류 코드로 종료하며 진단 로그에 비밀이 아닌 오류 종류만 남긴다.
- 트레이 미실행: 브리지가 같은 설치 폴더의 트레이 앱을 시작하고 2초 동안 IPC 연결을 재시도한다.
- 터미널 창 미확인: 프로젝트명·세션 ID로 알리고 클릭 시 작업 기록을 연다.

## 배포

- Windows 10/11 x64 대상
- .NET 8 자체 포함 단일 파일 게시
- 외부 NuGet 패키지 없음
- `build-windows.ps1`에서 Core 테스트 실행 후 `dotnet publish` 수행
- 산출물은 `artifacts/win-x64/CodexUsageTray.exe`와 `CodexUsageTray.EventBridge.exe`
- 설치 시 기존 `hooks.json`을 백업하고 앱 항목만 병합한다. 제거 시 앱 항목만 제거하고 다른 Hook은 보존한다.

## 테스트와 완료 기준

- 복수 버킷, 단일 호환 버킷, 누락 필드, 범위 밖 백분율, 초기화 시각을 자동 테스트한다.
- JSON-RPC 응답 ID 매칭, 알림 건너뛰기, 서버 오류 전달을 자동 테스트한다.
- 잔여율 임계값과 가장 제한적인 버킷 선택을 자동 테스트한다.
- 세 Hook 입력의 상태·프로젝트·채팅·요약 정규화를 자동 테스트한다.
- IPC 직렬화 왕복과 중복 작업 상태 갱신을 자동 테스트한다.
- Windows 빌드 스크립트가 테스트 성공 전에는 게시하지 않아야 한다.
- 실제 Windows에서는 아이콘 생성, 클릭 팝업, 자동/수동 갱신, 시작 프로그램 등록, 로그인 오류, Hook 신뢰, 승인·완료 팝업, 터미널 포커스를 수동 확인한다.

## 범위 제외

- 사용량 예측 및 비용 예측
- API Platform 토큰/비용 사용량
- 브라우저 화면 스크래핑
- 사용 제한 초기화권 소비
- 자동 로그인 또는 인증 정보 직접 보관
- 웹 ChatGPT 화면·브라우저 쿠키·Windows 알림 센터 역공학
- 공식 이벤트에 결과 상태가 없으므로 작업 실패를 응답 문구로 추측하는 기능

## 롤백

제거 스크립트로 앱 Hook 항목과 시작 프로그램 항목을 제거한 뒤 실행 파일 폴더를 삭제한다. 설치 전 Hook 백업을 보존하며 앱은 Codex 로그인 저장소를 수정하지 않는다.
