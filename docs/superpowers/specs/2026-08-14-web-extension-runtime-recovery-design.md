# 웹 ChatGPT 확장 런타임 무효화 대응 설계

## 목표

Chrome/Edge에서 압축해제 확장을 새로고침하거나 업데이트한 뒤 기존 ChatGPT 탭에 남은 content script가 `chrome.runtime.sendMessage`를 반복 호출하면서 오류를 쌓는 문제를 제거한다. 새로고침된 ChatGPT 탭에서는 기존과 동일하게 응답 완료·승인 요청 알림을 전달한다.

## 확인된 원인

- 사용자 환경에서 `content.js:79`의 `chrome.runtime.sendMessage`가 `chrome.runtime` 부재로 동기 `TypeError`를 발생시켰다.
- 확장 오류 화면의 `모두 삭제`는 기록만 지우며 기존 탭의 MutationObserver와 500ms 타이머는 계속 실행된다.
- 해당 ChatGPT 탭을 `Ctrl+Shift+R`로 다시 불러오자 완료 알림이 즉시 정상화됐다.
- 따라서 네이티브 호스트나 트레이 앱이 아니라 확장 새로고침 후 남은 무효화된 content script가 원인이다.

## 범위

### 포함

- 메시지 전송 전에 확장 런타임 사용 가능 여부 검사
- 동기 전송 예외와 비동기 전송 거부 처리
- 런타임 무효화가 확인되면 MutationObserver와 주기 타이머를 한 번만 종료
- 정상 런타임에서 완료·승인 메시지 전달 유지
- 설치·업데이트 안내에 기존 ChatGPT 탭 새로고침 절차 추가
- 회귀 테스트와 확장 버전 증가
- Windows 패키지 v1.2.5 릴리스

### 제외

- ChatGPT 탭 자동 새로고침: 생성 중인 응답이나 작성 중인 입력을 잃을 수 있다.
- `scripting` 권한을 추가한 content script 자동 재주입: 권한과 중복 감시 제어가 늘어나며 현재 문제에 과하다.
- ChatGPT DOM 완료 감지 규칙 변경
- Codex Hook, 트레이 팝업, 네이티브 메시징 프로토콜 변경

## 설계

### 런타임 메시지 경계

`runtime-messaging.js`를 새로 두고 content script에서 직접 `chrome.runtime.sendMessage`를 호출하지 않는다. 이 모듈은 다음 계약을 가진다.

1. `chrome.runtime`, `runtime.id`, `runtime.sendMessage`가 없으면 메시지를 보내지 않고 런타임 무효화 콜백을 호출한다.
2. `sendMessage`의 동기 예외를 포착한다. 확장 컨텍스트 무효화 오류이면 무효화 콜백을 호출한다.
3. 반환된 Promise의 거부를 소비해 확장 오류로 누적되지 않게 한다.
4. 수신자 일시 부재 같은 일반 전송 실패는 알림 한 건만 실패시키고 감시는 유지한다.
5. 정상 호출은 기존 메시지 구조를 바꾸지 않는다.

모듈은 브라우저에서는 전역 API로, Node 회귀 테스트에서는 CommonJS 모듈로 노출한다. 기존 `completion-state.js`와 같은 프로젝트 패턴을 따른다.

### 감시 생명주기

`content.js`는 MutationObserver와 interval ID를 보관한다. 런타임 무효화 콜백이 오면 다음을 수행한다.

- MutationObserver 연결 해제
- 500ms interval 해제
- 종료 상태 기록
- 이후 예약된 검사와 메시지 전송 무시

종료는 여러 번 호출돼도 부작용이 없는 멱등 동작이어야 한다. 새 확장 컨텍스트는 페이지 새로고침 때 새 content script로 다시 시작한다.

## 사용자 경험

- 현재 사용 중인 정상 탭: 변화 없음.
- 확장을 새로고침한 기존 탭: 오류가 반복 생성되지 않는다. 알림을 다시 받으려면 해당 ChatGPT 탭을 한 번 새로고침한다.
- 설치 출력과 확장 README: “확장 새로고침 후 열려 있던 ChatGPT 탭도 새로고침”을 명시한다.
- 앱이 사용자 작업 중인 ChatGPT 탭을 임의로 다시 불러오지 않는다.

## 테스트

Node 회귀 테스트에서 다음을 검증한다.

1. `chrome.runtime`이 없어도 예외를 던지지 않고 무효화로 판정한다.
2. `sendMessage`가 동기 무효화 오류를 던져도 예외가 밖으로 새지 않는다.
3. 비동기 전송 실패가 처리되지 않은 Promise 거부를 만들지 않는다.
4. 정상 런타임에는 기존 activity 메시지를 정확히 한 번 전달한다.
5. 런타임 무효화 시 감시 종료가 한 번만 수행된다.

기존 완료 상태 3개, 탭 포커스 4개 테스트와 JavaScript 구문 검사를 함께 실행한다. Windows CI에서는 패키지 빌드와 기존 EventBridge·설치 회귀 테스트도 유지한다.

## 배포와 롤백

- 확장 manifest 버전을 `1.1.1`로 올리고 앱 릴리스 태그를 `v1.2.5`로 배포한다.
- 설치 후 사용자는 확장 관리 화면에서 압축해제 확장을 새로고침하고 기존 ChatGPT 탭을 새로고침한다.
- 문제가 생기면 v1.2.4 릴리스 ZIP으로 재설치하고 확장 폴더를 다시 로드할 수 있다. 네이티브 호스트 형식과 Hook 설정은 바뀌지 않으므로 데이터 마이그레이션은 없다.

## 완료 기준

- 사용자 오류와 동일한 `chrome.runtime` 부재 재현 테스트가 수정 전 실패하고 수정 후 통과한다.
- 무효화된 탭에서 오류가 반복 누적되지 않는다.
- 새로고침한 탭에서 웹 응답 완료 팝업이 표시되고 클릭하면 기존 해당 채팅 탭으로 이동한다.
- Codex 완료 알림과 사용량 표시는 회귀하지 않는다.
- Windows CI와 릴리스 패키지 검증이 모두 통과한다.
